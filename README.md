# docker-image-optimization

The same Go service packaged five ways, from a naive one-stage Dockerfile to `FROM scratch`. Every variant is built, measured, scanned and smoke-tested by one script, and CI reruns the comparison on every change and weekly.

## The service

[`app/`](app) is a small HTTP API with Prometheus metrics:

| Endpoint | Returns |
|---|---|
| `GET /healthz` | `{"status": "ok", "version": "..."}` |
| `GET /time?tz=Asia/Kolkata` | the current time in that time zone |
| `GET /metrics` | Prometheus metrics, including a request counter |

It was chosen to expose the two things minimal images most often break: **time zone data**, and **health checks without a shell**. It also handles `SIGTERM` by draining connections, so `docker stop` returns at once instead of waiting 10 seconds to kill it.

## The five Dockerfiles

| Variant | What changes | What it fixes |
|---|---|---|
| [`01-naive`](dockerfiles/01-naive.Dockerfile) | One stage on `golang:1.27.4`, `COPY . .` then build | Nothing: the starting point most projects begin with |
| [`02-multistage`](dockerfiles/02-multistage.Dockerfile) | Build stage + `debian:trixie` runtime; `go.mod` copied before the code | The compiler, module cache and sources no longer ship. A code change reuses the dependency layer |
| [`03-alpine`](dockerfiles/03-alpine.Dockerfile) | Static binary (`CGO_ENABLED=0`, `-trimpath`, `-s -w`), BuildKit cache mounts, cross-compilation, non-root user, `alpine:3.24` | Much smaller base, a fast rebuild because only the changed package recompiles, no root |
| [`04-distroless`](dockerfiles/04-distroless.Dockerfile) | `gcr.io/distroless/static-debian13:nonroot` | No shell and no package manager to exploit, yet CA certificates, time zone data and a nonroot user are included |
| [`05-scratch`](dockerfiles/05-scratch.Dockerfile) | Empty base; time zone data embedded with `-tags timetzdata`; CA bundle copied in | Nothing in the image but the binary and the certificate bundle |

## What each column means

- **Size / Gzipped:** the unpacked filesystem, measured with `docker export`, and its gzipped size as an estimate of the download. (`docker image inspect` is not used: it reports the compressed size with the containerd image store and the unpacked size with overlay2.)
- **OS packages and CVEs:** from a Trivy scan. In the measured run every vulnerability in `01-naive` and `02-multistage` was in Debian OS packages the service never uses; the Go binary itself had none. The fix is not patching faster but shipping less.
- **Shell:** whether `/bin/sh` exists. Without one, an attacker who gets code execution has far less to work with, and so do you when debugging (attach a debug container instead, for example `kubectl debug` or `docker run --pid=container:<id> --network=container:<id> busybox`).
- **Rebuild after code change:** a one-line change to `main.go` with a warm cache. `01-naive` re-downloads every module because `COPY . .` comes before the build; `02` keeps the modules but recompiles them; `03`–`05` recompile only the changed package thanks to cache mounts.
- **Startup / graceful stop:** time until `/healthz` answers, and how long `docker stop` takes.
- **Smoke tests:** `/healthz`, `/time?tz=Asia/Kolkata`, `/metrics`, and the image's own `HEALTHCHECK` reaching `healthy`.

## Gotchas this project runs into

**`scratch` has no time zone data.** Built without `-tags timetzdata`, the scratch image still starts and still answers in UTC, so a quick test passes, but:

```console
$ curl 'localhost:8080/time?tz=Asia/Kolkata'
{"error":"unknown time zone Asia/Kolkata"}
```

The smoke test asks for a non-UTC zone for exactly this reason.

**`HEALTHCHECK CMD curl ...` cannot work without a shell or curl.** The binary has a `-healthcheck` flag that probes its own `/healthz` and exits 0 or 1, used by every variant.

**`scratch` and distroless images have no CA certificates or users by default.** Distroless includes both; for scratch the CA bundle is copied from the build stage and the user is set numerically (`USER 65532:65532`), since there is no `/etc/passwd`.

**Smaller is not automatically better.** Alpine uses musl instead of glibc, which matters for cgo and some DNS setups; this static binary avoids both. Distroless or scratch images need a debug strategy because you cannot `docker exec` into a shell.

## Run it yourself

Requirements: Docker with BuildKit (Docker Desktop, Colima or Docker Engine 23+), Trivy, Python 3.9+.

```sh
python3 scripts/benchmark.py              # all variants; updates the table above
python3 scripts/benchmark.py 05-scratch   # just one

# or build and run one directly
docker build -f dockerfiles/05-scratch.Dockerfile -t timeapi:scratch app
docker run --rm -p 8080:8080 timeapi:scratch
curl 'localhost:8080/time?tz=Asia/Kolkata'
```

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml), on every pull request, push to `main`, and weekly:

1. `gofmt`, `go vet`, `go test -race`
2. hadolint on every Dockerfile
3. the benchmark: builds every variant, runs the smoke tests (the job fails if any fails), scans with Trivy, and publishes the table in the job summary and as an artifact

All actions are pinned to commit SHAs.
